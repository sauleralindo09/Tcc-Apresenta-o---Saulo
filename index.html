Antes de começar: entenda o OS-Mobile

Os slides apresentam um sistema de gestão e acompanhamento de Ordens de Serviço de manutenção de aparelhos.

Visão do cliente

O cliente se cadastra, registra o aparelho, consulta a Ordem de Serviço, visualiza o orçamento e responde à proposta.

Visão administrativa

O administrador consulta as ordens, analisa as informações do aparelho, informa o orçamento e acompanha o andamento do serviço.

Ideia central: o cliente utiliza o sistema para acompanhar sua solicitação; a assistência utiliza o sistema para administrar as Ordens de Serviço e os serviços realizados.

1. Tecnologias e ferramentas

O primeiro slide mostra quais tecnologias e ferramentas foram utilizadas e a responsabilidade de cada uma.

HTML

Cria a estrutura das páginas, como títulos, textos, campos de formulário e botões.

CSS

Define a aparência das páginas: cores, fontes, tamanhos, espaçamentos e organização dos elementos.

JavaScript

Adiciona interatividade e comportamento às páginas, permitindo que elas respondam às ações do usuário.

Python

Linguagem utilizada no backend para desenvolver a lógica executada no servidor.

Flask

Framework de Python utilizado para criar o servidor e os endpoints, isto é, as rotas da API.

MySQL

Banco de dados utilizado para armazenar e organizar as informações do sistema.

JWT

Padrão de token que pode ser utilizado na autenticação para representar informações de uma sessão ou usuário autenticado.

Werkzeug

Biblioteca do ecossistema Python/Flask. Entre seus recursos, oferece funções para gerar e verificar hashes de senhas.

Trello

Ajuda a equipe a organizar tarefas e acompanhar o andamento do desenvolvimento.

draw.io

Ferramenta utilizada para criar diagramas e representar processos e estruturas visualmente.

Figma

Ferramenta utilizada para criar protótipos das telas e planejar a navegação e a aparência do sistema.

Ferramentas de apoio

VS Code é o editor de código; Google Drive auxilia no armazenamento e compartilhamento de arquivos; Excalidraw permite criar desenhos e esquemas.

Roteiro pronto para apresentar

Neste slide, apresentamos as principais tecnologias e ferramentas utilizadas no desenvolvimento do OS-Mobile.

No frontend, utilizamos HTML para estruturar as páginas, CSS para definir a aparência e JavaScript para adicionar interatividade.

No backend, utilizamos Python com Flask, responsáveis pela lógica do servidor e pela criação dos endpoints da API. Para armazenar as informações, utilizamos o MySQL.

Também temos o JWT e o Werkzeug, relacionados à autenticação e à segurança das senhas. Para organização, modelagem e prototipação, utilizamos Trello, draw.io e Figma. Como ferramentas de apoio, utilizamos VS Code, Google Drive e Excalidraw.

Se perguntarem: JWT e hash de senha são a mesma coisa?

Não. JWT é um token utilizado em mecanismos de autenticação. Hash de senha é uma representação protegida da senha, usada para verificar a senha informada sem guardar a senha original em texto puro. São conceitos diferentes.

2. Como as partes se comunicam

O segundo slide explica a comunicação entre frontend, backend e banco de dados.

FRONTEND HTML • CSS • JavaScript

Parte visual com que o usuário interage.

BACKEND Python • Flask • API

Recebe e processa as solicitações.

BANCO DE DADOS MySQL

Armazena e fornece as informações.

Exemplo: o cliente consulta uma Ordem de Serviço

  1. O cliente abre a tela de consulta no frontend.
  2. O frontend envia uma requisição HTTP para um endpoint da API.
  3. As informações podem ser organizadas e transportadas em formato JSON.
  4. O backend, desenvolvido com Python e Flask, recebe a solicitação e executa a lógica necessária.
  5. Quando precisa dos dados, o backend consulta o banco MySQL.
  6. O banco retorna os dados ao backend.
  7. O backend envia uma resposta ao frontend, que apresenta o resultado ao cliente.

HTTP

É o protocolo utilizado na comunicação entre aplicações por meio de requisições e respostas.

JSON

É um formato de dados usado para organizar e transportar informações, por exemplo, dados de uma Ordem de Serviço.

API e endpoint

A API permite a comunicação entre partes do sistema. Um endpoint é uma rota específica que recebe uma solicitação e executa uma operação.

Por que o backend é necessário?

Ele processa as solicitações e aplica as regras do sistema. Na arquitetura apresentada, o frontend não acessa diretamente o banco de dados.

Roteiro pronto para apresentar

Aqui mostramos como as três partes principais do sistema se comunicam.

Primeiro, temos o frontend, que é a parte visual onde o usuário realiza as ações. Quando o usuário faz uma solicitação, o frontend envia uma requisição HTTP para a API, utilizando JSON para organizar e transportar os dados.

O backend, desenvolvido com Python e Flask, recebe essa requisição, valida e processa as informações. Quando necessário, consulta ou atualiza o banco de dados MySQL.

Depois, o backend envia uma resposta ao frontend, onde o resultado é apresentado ao usuário.

3. Fluxo do cliente

O terceiro slide mostra a sequência de ações que o cliente realiza dentro do OS-Mobile.

  1. Cadastro e login: o cliente cria uma conta e acessa o sistema.
  2. Registro do aparelho: informa os dados do aparelho que deseja encaminhar para manutenção.
  3. Consulta da ordem: consulta as informações da sua Ordem de Serviço.
  4. Visualização do orçamento: verifica o valor informado pela assistência.
  5. Resposta ao orçamento: informa se aceita ou não o orçamento apresentado.

Acompanhamento

O cliente consulta suas informações e o status da solicitação para acompanhar o andamento da Ordem de Serviço.

Contato

O sistema oferece um atalho para abrir o WhatsApp com os dados da ordem preenchidos, facilitando o contato.

Roteiro pronto para apresentar

Neste slide, apresentamos o fluxo do cliente dentro do OS-Mobile.

Primeiro, ele realiza o cadastro e o login. Depois, registra o aparelho que deseja enviar para manutenção.

Em seguida, pode consultar sua Ordem de Serviço e visualizar o orçamento informado pela assistência. Após visualizar o valor, o cliente pode responder se aceita ou não o orçamento.

Além disso, o sistema permite acompanhar o status da solicitação e disponibiliza um atalho para entrar em contato pelo WhatsApp, com os dados da ordem preenchidos.

Para memorizar: o foco do fluxo do cliente é registrar o aparelho, consultar a ordem, visualizar o orçamento e responder.

4. Fluxo administrativo

O quarto slide mostra as atividades realizadas pela assistência técnica ou pelo responsável administrativo.

  1. Receber e consultar as Ordens de Serviço: visualizar as ordens cadastradas pelos clientes.
  2. Analisar as informações do aparelho: verificar os dados do aparelho e o problema informado.
  3. Informar o valor do orçamento: registrar o valor que será apresentado ao cliente.
  4. Acompanhar a resposta do cliente: verificar se o cliente aceitou ou não o orçamento.
  5. Atualizar e acompanhar os registros do serviço: manter as informações e o andamento do atendimento atualizados.

Os três status das solicitações

PENDENTES: solicitações que aguardam ação.

EM EXECUÇÃO: serviços que estão em andamento.

FINALIZADOS: serviços que já foram concluídos.

Roteiro pronto para apresentar

Agora temos o fluxo administrativo, que representa as atividades realizadas pela assistência técnica.

Primeiro, o administrador recebe e consulta as Ordens de Serviço cadastradas pelos clientes. Depois, analisa as informações do aparelho e informa o valor do orçamento.

Em seguida, acompanha a resposta do cliente para saber se ele aceitou ou não o valor apresentado. Por fim, atualiza os registros e acompanha o andamento dos serviços.

Para facilitar esse controle, o sistema organiza as solicitações em três status: pendentes, em execução e finalizados. Assim, o administrador consegue identificar quais serviços aguardam uma ação, quais estão em andamento e quais já foram concluídos.

Para memorizar: o foco administrativo é consultar, analisar, informar o orçamento, acompanhar a resposta e atualizar os registros.

Perguntas que podem aparecer na banca

Abra cada pergunta para estudar uma resposta curta.

1. Qual é a diferença entre frontend e backend?

Frontend é a parte visual com que o usuário interage. Backend é responsável pela lógica do sistema, pelo processamento das solicitações e pela comunicação com o banco.

2. O que é uma API?

É uma interface que permite a comunicação entre partes do sistema. No projeto, recebe solicitações do frontend e retorna respostas.

3. Para que serve o MySQL?

Para armazenar e organizar as informações utilizadas pelo sistema.

4. O que é Flask?

É um framework de Python que facilita a criação do servidor e das rotas da API.

5. Para que serve o JWT?

É um padrão de token que pode ser utilizado em mecanismos de autenticação e controle de acesso.

6. Para que serve o Werkzeug?

É uma biblioteca do ecossistema Flask que oferece, entre outros recursos, funções para gerar e verificar hashes de senhas.

7. O que é uma requisição HTTP?

É uma solicitação enviada de uma aplicação para outra, como uma solicitação do frontend para o backend.

8. O que é JSON?

É um formato usado para organizar e transportar dados de maneira estruturada.

9. Qual é a diferença entre o fluxo do cliente e o administrativo?

O cliente registra o aparelho, consulta a ordem e responde ao orçamento. O administrador gerencia as ordens, analisa os aparelhos, informa orçamentos e acompanha os serviços.

10. Por que existem três status?

Para facilitar a organização e o acompanhamento: separar solicitações que aguardam ação, serviços em andamento e serviços concluídos.

11. O frontend acessa diretamente o banco de dados?

Na arquitetura apresentada, não. O frontend envia solicitações à API; o backend processa e acessa o MySQL quando necessário.

12. O que acontece depois que o cliente responde ao orçamento?

O administrador acompanha a resposta e atualiza os registros do serviço conforme o andamento do atendimento. O slide não detalha outras regras para cada tipo de resposta.
